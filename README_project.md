# Telco Customer Churn Prediction

A machine learning project that builds a predictive pipeline to identify IBM Telco customers who are likely to churn, enabling the business to take proactive retention action before those customers leave.

---

## Project Structure

```
telco-churn-prediction/
├── telco_churn.ipynb          # Main notebook — all 6 pipeline stages in one narrative file
├── requirements.txt           # Python dependencies with minimum version pins
├── README.md                  # This file — setup and execution instructions
├── report.md                  # Auto-generated by the notebook's final cell
└── figures/                   # Auto-created by the notebook at runtime
    ├── eda_churn_distribution.png
    ├── eda_numeric_distributions.png
    ├── eda_correlation_heatmap.png
    ├── eda_categorical_churn_rates.png
    ├── roc_curves.png
    ├── rf_feature_importance.png
    └── shap_summary.png       # Generated only if shap is installed
```

> **Note:** `report.md` and the `figures/` directory are created automatically when you run the notebook from top to bottom. They are not present in the repository by default.

---

## Prerequisites

- **Python ≥ 3.9**
- `pip` (comes bundled with Python)
- An internet connection is recommended so the notebook can auto-download the dataset (see [Dataset](#dataset) for offline fallback)

---

## Setup

### 1. Clone or download the project

```bash
git clone <repository-url>
cd telco-churn-prediction
```

Or simply unzip/copy the project folder and `cd` into it.

### 2. Create a virtual environment

```bash
python -m venv venv
```

### 3. Activate the virtual environment

**Windows (PowerShell / CMD):**
```powershell
venv\Scripts\activate
```

**macOS / Linux:**
```bash
source venv/bin/activate
```

### 4. Install dependencies

```bash
pip install -r requirements.txt
```

This installs all required packages including `shap` for optional model explainability. If you encounter issues installing `shap`, it can be safely skipped — the notebook detects its absence and skips the SHAP section automatically.

---

## Dataset

The notebook automatically downloads the **IBM Telco Customer Churn** dataset from the IBM GitHub repository at startup:

```
https://raw.githubusercontent.com/IBM/telco-customer-churn-on-icp4d/master/data/Telco-Customer-Churn.csv
```

**Offline fallback:** If you are running without an internet connection, download the CSV manually and place it in the project directory as:

```
telco-churn-prediction/Telco-Customer-Churn.csv
```

The notebook will detect the failed URL download and fall back to this local file automatically.

---

## Running the Notebook

Launch the Jupyter Notebook server from inside the project directory:

```bash
jupyter notebook telco_churn.ipynb
```

Then run all cells from top to bottom (**Kernel → Restart & Run All** is the recommended approach for a clean, reproducible run).

The six pipeline stages in the notebook are:

| Stage | Description |
|---|---|
| 1 | Data Loading & Initial Inspection |
| 2 | Exploratory Data Analysis (EDA) |
| 3 | Data Preprocessing |
| 4 | Model Training |
| 5 | Model Evaluation |
| 6 | Report Generation |

---

## Output Files

After a full notebook run, the following files are produced:

| File | Description |
|---|---|
| `report.md` | Standalone Markdown report summarising EDA findings, model comparison metrics, the recommended best model, and evidence-backed business retention recommendations |
| `figures/eda_churn_distribution.png` | Class balance bar chart |
| `figures/eda_numeric_distributions.png` | KDE distributions of numeric features split by churn |
| `figures/eda_correlation_heatmap.png` | Correlation heatmap of numeric features |
| `figures/eda_categorical_churn_rates.png` | Churn rate by key categorical features |
| `figures/roc_curves.png` | Overlaid ROC curves for all three models |
| `figures/rf_feature_importance.png` | Top 15 features by Random Forest importance |
| `figures/shap_summary.png` | SHAP beeswarm summary plot (only if `shap` is installed) |

---

## Models Trained

| Model | Key Settings |
|---|---|
| Logistic Regression | `max_iter=1000`, `random_state=42` |
| Random Forest | `n_estimators=100`, `random_state=42` |
| Gradient Boosting | `n_estimators=100`, `learning_rate=0.1`, `random_state=42` |

Models are compared on Accuracy, Precision, Recall, F1-Score, and ROC-AUC. The best model by ROC-AUC is highlighted in `report.md`.

---

## Reproducibility

All random states are fixed at `42`. Running **Kernel → Restart & Run All** on a clean environment will produce identical results every time.
